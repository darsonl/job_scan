# Mode: apply-104 — Auto-Apply Assistant for 104.com.tw

Automatic workflow with Playwright to apply to jobs on 104.com.tw using data from the evaluation report generated by the pipeline.

**Always dispatched as subagent** (same as `apply` and `pipeline`).

---

## ETHICAL RULES — MANDATORY (CLAUDE.md)

- **NEVER click Submit/送出應徵 without explicit user confirmation**
- **Score < 3.5 → block** (requires explicit override by typing `YES`)
- **Score 3.5–3.9 → warn** and request confirmation before continuing
- Quality over quantity — do not apply if the match is not genuine

---

## Step 0 — Input Resolution

The argument can be a pipeline number (`#xxx`) or a direct 104.com.tw URL.

**If the argument is `#xxx` (pipeline number):**
- `Read("data/pipeline.md")`
- Find the line in the `## Processed` section containing `#xxx |` (regex: `#0*{num}\s*\|`)
- Extract the URL from the second field: `- [x] #{num} | {URL} | ...`
- If the line does not exist → STOP: "Report #{num} not found in data/pipeline.md Processed section."
- If the URL is not from 104.com.tw → STOP: "Report #{num} URL is not a 104.com.tw job. Use `/career-ops apply` for non-104 portals."
- Use the extracted URL as input for the following steps.

**If the argument is a direct 104.com.tw URL:**
- Use the URL as-is.

---

## Step 0b — Pre-conditions

Load Playwright tools via ToolSearch:

```
ToolSearch("select:mcp__plugin_playwright_playwright__browser_navigate,mcp__plugin_playwright_playwright__browser_snapshot,mcp__plugin_playwright_playwright__browser_close,mcp__plugin_playwright_playwright__browser_click,mcp__plugin_playwright_playwright__browser_wait_for,mcp__plugin_playwright_playwright__browser_fill_form,mcp__plugin_playwright_playwright__browser_take_screenshot,AskUserQuestion")
```

Load credentials:
- `Read("config/portals-credentials.yml")`
- Extract `portals.104.email` and `portals.104.password`
- If the file does not exist or fields are empty → STOP:
  > "Create `config/portals-credentials.yml` first. Template:
  > ```yaml
  > portals:
  >   104:
  >     email: "your-104-email"
  >     password: "your-104-password"
  >     resume_id: ""   # optional: 104 saved resume ID
  > ```"

## Step 1 — Load Evaluation Report

Extract `jobNo` from the input URL. Pattern: `104\.com\.tw/job/([^/?#\s]+)`.

Search in reports/:

```
Grep(pattern="\\*\\*URL:\\*\\*.*104\\.com\\.tw/job/{jobNo}", path="reports/", glob="*.md")
```

**If match found:**
- Read the full report
- Extract: Score (line `**Score:**`), Company + Role (title `# Company — Role`), Legitimacy (line `**Legitimacy:**`)
- Look for section `## H) Draft Application Answers` — load if it exists

**If no match:**
- Warn: "No evaluation report found for `104.com.tw/job/{jobNo}`. Run `/career-ops {URL}` first to evaluate, then retry."
- Offer to continue in degraded mode (no score gate, no draft answers). If user declines → exit.

---

## Step 1b — Pre-Generate Cover Letter

Before opening the browser, load candidate materials and generate the cover letter text. This keeps the Playwright session fast — no LLM generation inside a live browser session.

Read now:
- `Read("cv.md")`
- `Read("article-digest.md")` — skip silently if file does not exist
- `Read("config/profile.yml")` — extract `compensation.target_range`

Using the loaded report (Step 1) + cv.md + article-digest.md, pre-generate:

**`cover_letter_text`** (≤300 words, following `modes/_writing-rules.md`, language matching JD):
- Opening: reference the specific role and one concrete signal from the JD
- Body: 2–3 proof points from cv.md / article-digest.md mapped to JD requirements
- Close: one sentence on availability / readiness

**`self_intro_text`** (≤150 words, Mandarin if JD is in Mandarin):
- Use Block A proof points from the report as basis

Store both as named variables for use in Step 7B. Do NOT open the browser yet.

If no report was loaded (degraded mode from Step 1): generate from cv.md alone, using the job URL as the only JD signal available.

## Step 2 — Score Gate

If report was loaded:

**Score < 3.5:**

```
AskUserQuestion(questions=[{
  "question": "Score is {X}/5 — below the recommended threshold of 3.5.\nCLAUDE.md rules recommend against applying.\nOnly override if you have a specific reason (referral, unique circumstance, etc.).",
  "header": "Score Warning",
  "options": [
    {"label": "YES — Override", "description": "I have a specific reason to apply despite the low score"},
    {"label": "Cancel", "description": "Abort — recommended action"}
  ]
}])
```

Only continue if user selects "YES — Override". Any other selection → `browser_close()` and exit.

**Score 3.5–3.9:**

```
AskUserQuestion(questions=[{
  "question": "Score is {X}/5 — decent but not an ideal match. Applying is possible but not recommended.",
  "header": "Score Warning",
  "options": [
    {"label": "Proceed", "description": "Continue with the application"},
    {"label": "Cancel", "description": "Abort — look for a better match first"}
  ]
}])
```

Only continue if user selects "Proceed".

**Score ≥ 4.0:**
Continue automatically.

---

## Step 3 — Login Check

```
browser_navigate("https://www.104.com.tw/member/login")
browser_snapshot()
```

**If already logged in** (snapshot shows user menu, avatar, or absence of login form):
→ Skip to Step 4.

**If login form appears:**
- Detect captcha: if snapshot contains text `請完成驗證` or `滑動解鎖`:
  ```
  AskUserQuestion(questions=[{
    "question": "A slider CAPTCHA appeared on the 104 login page. Complete it manually in the browser window, then select Done.",
    "header": "CAPTCHA Required",
    "options": [
      {"label": "Done", "description": "I completed the CAPTCHA — proceed with login"},
      {"label": "Cancel", "description": "Abort the application"}
    ]
  }])
  ```
  If Cancel → `browser_close()` and exit. If Done → `browser_snapshot()` to confirm CAPTCHA cleared, then continue.
- Fill credentials: `browser_fill_form({"input[name='id']": email, "input[name='passwd']": password})`
  (104 uses `id` and `passwd` as field names in its login form)
- Click login: `browser_click("button[type='submit']")` or button with text `登入`
- **Detect OTP/MFA:** Take snapshot immediately after click. If snapshot contains `驗證碼`, `OTP`, `Email Verification`, `電子郵件驗證`, or a 6-digit input field:
  ```
  AskUserQuestion(questions=[{
    "question": "104 sent an email verification code to {first 3 chars of email}***@{domain}. Type the 6-digit code in 'Other', or select the manual option.",
    "header": "Email Verification (MFA)",
    "options": [
      {"label": "I'll handle it manually", "description": "Complete in browser, then I'll verify login succeeded"}
    ]
  }])
  ```
  - If `answer.text` matches `/^\d{6}$/` → fill the OTP field via `browser_fill_form` and click confirm.
  - If user selects "I'll handle it manually" (or any non-numeric response) → wait, then `browser_snapshot()` to confirm login before continuing.
- `browser_wait_for(text="登出", timeout=10000)` — "登出" (logout link) confirms successful login
- `browser_snapshot()` — confirm login
- If still on login page → STOP: "Login failed. Verify credentials in `config/portals-credentials.yml`."

## Step 4 — Navigate to Job

```
browser_navigate("https://www.104.com.tw/job/{jobNo}")
browser_wait_for(text="立即應徵", timeout=10000)
browser_snapshot()
```

Verify the job is active:
- The page must show the "立即應徵" or "投遞履歷" button
- If `此職缺已截止`, `已下架`, or `職缺不存在` appears → STOP: "Job posting is closed or removed."
- If the title on screen differs significantly from the report → warn user before continuing

## Step 5 — Pre-Flight Gate (MANDATORY — NEVER SKIP)

**NEVER skip this step.** Before touching the apply button, invoke:

```
AskUserQuestion(questions=[{
  "question": "Ready to apply?\n\nCompany:    {Company}\nRole:       {Role}\nURL:        https://www.104.com.tw/job/{jobNo}\nScore:      {X}/5  |  Legitimacy: {tier}\nReport:     {report filename}\nCover letter: pre-generated ({word count} words)\nAccount:    {email from portals-credentials.yml}",
  "header": "Pre-Flight Summary",
  "options": [
    {"label": "APPLY", "description": "Proceed — click the apply button now"},
    {"label": "Cancel", "description": "Abort — no changes made, browser will close"}
  ]
}])
```

If user selects Cancel (or any answer other than APPLY):
- `browser_close()`
- Exit.

If user selects APPLY → continue with Step 6.

---

## Step 6 — Click Apply and Detect Form Type

```
browser_click(selector for "立即應徵" or "投遞履歷")
browser_wait_for(timeout=3000)
browser_snapshot()
```

**Detect flow:**

**Quick Apply** — indicators in snapshot (any):
- Radio buttons or cards with resume names
- Heading "選擇履歷" or "選擇應徵資料"
- No `<textarea>` visible in the modal
- "確認應徵" or "送出應徵" button visible immediately without text fields

**Questionnaire** — indicators in snapshot (any):
- `<textarea>` elements present
- Fields for 自我介紹, 求職信, or custom questions
- URL changed to `/apply` or step/progress indicators present

If unclear → treat as Questionnaire (safer).

---

## Step 7A — Quick Apply Flow

From the snapshot, list the available saved resumes.

If `portals.104.resume_id` is defined in credentials:
- Find the radio button or card matching that ID and select it.

If not defined:
- Ask user: "Which resume should I use? Options: {list from snapshot}"
- Or auto-select the first (most recent) if user doesn't respond.

**Do NOT click confirm yet.** Take screenshot:

```
browser_take_screenshot()
```

Show user:

```
"Quick Apply: Selected resume '{resume name}'.
Screenshot above shows the current state.
→ Proceeding to review gate before submitting."
```

→ Go to Step 8.

---

## Step 7B — Questionnaire Flow

> **Note:** Cover letter and self-introduction text were pre-generated in Step 1b. Do not re-generate here — use `cover_letter_text` and `self_intro_text` directly in `browser_fill_form`.

For each visible field in the form:

**1. Identify field type and label** from the snapshot.

**2. Select answer:**
- If Section H exists in the report → find answer with fuzzy matching by concept:
  - "自我介紹" / "Tell us about yourself" → use pre-generated `self_intro_text` (adapt if Section H has a better version)
  - "為何應徵此職缺" / "Why this role" → use Block B alignment from the report
  - "期望薪資" / Expected salary → use `compensation.target_range` lower bound from `config/profile.yml`
  - "相關經歷" / Work experience → use proof points from Block A of the report
- If no Section H → use `cover_letter_text` and `self_intro_text` pre-generated in Step 1b. Do not regenerate here.
- If field is in Mandarin → respond in Mandarin, professional tone, no clichés

**3. Fill fields with `browser_fill_form`:**

Common 104 selectors:
- Cover letter / 求職信: `textarea[name="coverLetter"]` or `#coverLetter`
- Self intro / 自我介紹: `textarea[name="selfIntro"]` or `textarea` in 自我介紹 section
- Expected salary: `input[name="salary"]` or `input[placeholder*="薪資"]`
- Availability / 可上班日: `select[name="available"]`

If a named selector fails → use positional heuristic (`nth-of-type`) and notify user.

**4. Scroll check:** Scroll to bottom and take another snapshot. If more fields are visible → repeat the process.

Take final screenshot of filled form:

```
browser_take_screenshot()
```

→ Go to Step 8.

---

## Step 8 — Submission Confirmation Gate (MANDATORY — NEVER SKIP)

Take screenshot of filled form: `browser_take_screenshot()`

Build field summary (field label + first 80 chars of value), then invoke:

```
AskUserQuestion(questions=[{
  "question": "Form is ready.\n\nFields filled:\n  {field_label_1}: {value_preview_1}\n  {field_label_2}: {value_preview_2}\n  ...\n\n⚠️ I will NOT click Submit until you confirm.",
  "header": "Submit Confirmation",
  "options": [
    {"label": "SUBMIT", "description": "Click the submit button now — application will be sent"},
    {"label": "EDIT", "description": "Change a field first — you'll be asked which field and new value"},
    {"label": "Cancel", "description": "Abort — no submission made, browser will close"}
  ]
}])
```

**If user selects SUBMIT:**
→ Go to Step 9.

**If user selects EDIT:**

```
AskUserQuestion(questions=[{
  "question": "Which field to change? Type in 'Other' as: 'field name: new value' (e.g. 'Expected salary: 70000')",
  "header": "Edit Field",
  "options": [
    {"label": "Cancel edit", "description": "Go back to submit confirmation without changing anything"}
  ]
}])
```

- If user selects "Cancel edit" → return to start of Step 8.
- If user types in "Other": parse `field_name: new_value` from `answer.text`, update with `browser_fill_form`, take new screenshot, return to start of Step 8.

**If user selects Cancel:**
- "Application cancelled. No submission made."
- `browser_close()`
- Exit.

## Step 9 — Submit

```
browser_click(button with text "確認應徵" or "送出應徵" or "送出")
browser_wait_for(text="已成功應徵" OR "應徵成功" OR "感謝您的應徵", timeout=10000)
browser_snapshot()
```

Verify success:
- If page shows a confirmation message (成功/感謝/confirmation banner) → success
- If still on the form → warn: "Submission may have failed — page did not show a confirmation. Please check manually." Do not mark as Applied.

```
browser_take_screenshot()
```

   - If the row exists → change status from `Evaluated` to `Applied`.
   - If not exists → create TSV entry in `batch/tracker-additions/{num}-{company-slug}.tsv` with status `Applied`.

"✓ Applied successfully to {Company} — {Role}.

  Suggested next step:
  → /career-ops contact {Company} to find LinkedIn contacts and draft an outreach message."
```

## Implementation Notes

**Captcha on login:** 104 uses slider CAPTCHA on new devices or after extended inactivity. Detect by text `請完成驗證` or `滑動解鎖` in the snapshot → invoke AskUserQuestion with a "Done" option for the user to confirm when they've completed the CAPTCHA manually (see Step 3). Do NOT use a text STOP — keep the subagent alive.

**OTP/MFA on login:** If 104 requests an email verification code after login, invoke AskUserQuestion with the "Other" field for the user to type the 6-digit code. Extract from `answer.text` (must match `/^\d{6}$/`) and fill via `browser_fill_form`. If the user prefers to handle it manually, take a new snapshot to confirm login before continuing (see Step 3).

**Session persistence:** Playwright MCP sessions do not persist cookies between Claude Code sessions. Login is required on each fresh invocation — Step 3 always verifies.

**Selector fallback:** If named selectors fail (104 redesigns the form), use positional heuristic (`nth-of-type`) in order of appearance in the snapshot. Notify user if fallback was used.

**Quick Apply + questionnaire hybrid:** Some postings first show the resume selector and then a short questionnaire. Treat as Questionnaire flow — CV selector fields are processed before text fields.

**Browser reset:** If `browser_navigate` fails with "Target page, context or browser has been closed" → call `browser_close()` once to reset MCP state, then retry.
